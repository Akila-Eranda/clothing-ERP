## 4. Safe-order principles for the rotation
Rotate in this order to avoid self-lock-out: **SSH access first (key-based, with a second session open) → server-side secrets → application secrets → external services.** Never edit `.env` and recreate containers in one unobserved step; take a backup first (§9 step 1). Do not rotate Postgres by changing `.env` alone: `POSTGRES_PASSWORD` is applied only at first DB initialisation, so the password must also be changed in the database.
